## 1. 想定した課題

高級宿の Web サイトは、写真が良ければ成立すると思われがちです。しかし実際の宿泊予約では、次の 3 つで離脱が起きます。

1. **料金の見通しが立たない** — 「1 泊 68,000 円〜」の「〜」が不安になる。人数・食事・オプションを足したときの総額が最後まで分からない。
2. **部屋の違いが分からない** — 3 棟あっても、写真の雰囲気しか違いが伝わらず、自分向きの部屋を選べない。
3. **スマホで予約まで進めない** — PC 前提で作られた予約フォームは、スマホでは項目が多すぎて指が止まる。

「泊まりたい」と思わせるビジュアルと、「泊まれそう」と判断させる情報設計。この 2 つを同じサイトの中で両立させることを、本プロジェクトの主題としました。

## 2. ターゲット

- 30〜50 代、首都圏在住の夫婦・カップル・少人数の友人グループ
- 1 泊 5〜10 万円の宿泊費を許容する層
- 人の多いホテルよりプライベートな空間を好み、サウナ・建築・料理・自然への関心が高い
- **検討はスマートフォン、比較検討の一部を PC** という行動を前提に設計

想定する心理遷移は以下の通りです。

```
ここに泊まりたい  →  部屋と料金を見る  →  条件を確かめる  →  予約に進む
   （TOP HERO）      （STAY / 料金表）    （FAQ / ACCESS）   （BOOKING）
```

## 3. 情報設計

- **1 ページ LP にしない。** 宿泊施設の検討行動は「客室を比べる」「サウナの詳細を読む」「アクセスを確かめる」と分岐します。ページを分けたうえで、どのページからも予約に戻れる導線（ヘッダー CTA・スマホ固定 CTA・各ページ末尾の FINAL CTA）を用意しました。
- **TOP は「読ませる」より「決めさせる」構成。** HERO → 世界観 → 客室 → サウナ → 体験 → **料金シミュレーター** → 立地 → ギャラリー → FAQ → 予約 CTA。料金という現実的な情報を、感情が高まった直後（体験セクションの後）に置いています。
- **FAQ を 2 か所に置く。** TOP には各カテゴリ 2 件の抜粋、ACCESS ページに全 20 件。TOP で不安を先回りしつつ、詳細を読みたい人だけを深いページへ送ります。

## 4. デザインコンセプト

コンセプトは **「熱と静寂に泊まる。」**。火（ember）と苔（moss）という 2 つの温度差をブランドの軸にしました。

- **カラー** — Obsidian `#0C0E0D` を基調に、Deep Forest / Warm Stone / Ivory で面を切り替え、Ember `#B87643` は CTA と数値の強調にのみ使用。アクセントを乱用せず、押すべき場所を 1 画面に 1 つだけにしています。
- **タイポグラフィ** — 大見出しは明朝（しっぽり明朝）で余白と品を、本文はゴシック（Zen Kaku Gothic New）で可読性を確保。ラベルと数値は Jost を字間広めの大文字で使い、装飾として機能させています。見出しは `clamp()` による流体スケール、日本語は `word-break: auto-phrase` で文節改行。
- **面の切り替え** — セクションごとに Obsidian / Deep Forest / Ivory / Warm Stone を交互に敷き、長いページでもリズムが単調にならないようにしました。角丸はほぼ使わず、罫線と余白で構造を見せています。
- **写真** — 全 20 カットを「1 本のブランド撮影」として設計し、被写体・構図・光・色調・禁止事項まで仕様化（`docs/image-production.md`）。差し替え前でも比率とトーンを合わせた仮画像でレイアウトを検証できる構造にしています。

## 5. コンバージョン設計

| 施策 | 意図 |
| --- | --- |
| TOP 内の料金シミュレーター | 「〜」で終わる価格表示の不安を、その場の操作で解消する |
| 条件の引き継ぎ（URL パラメータ + localStorage） | TOP で作った条件を予約ページで再入力させない |
| スマホ画面下部の固定 CTA（料金・空室を見る） | スクロール位置に関係なく、常に次の行動を提示する |
| 5 ステップの予約 UI | 1 画面 1 タスクにして、スマホでの入力負荷を下げる |
| ステップごとの即時バリデーション | 最後にまとめてエラーを出さない |
| 定員オーバーのヴィラを選択不可にする | 選べない選択肢を選ばせて後で否定しない |
| 予約サマリーの常時表示 | 合計金額が常に見えている状態で意思決定させる |
| 日付連動の空室表示（残りわずか / 満室） | 「空室を見る」という CTA の約束を UI 上で果たし、希少性を正直に伝える |
| FAQ をアコーディオンで一覧提示 | 不安要素（子ども・ペット・キャンセル・タトゥー）を検索させずに解消する |

## 6. 実装上の工夫

- **空室状況のデモ実装** — 日付とヴィラ ID から決定的に状態を生成しています（`src/lib/availability.ts`）。ランダムではないため、同じ日付を開けば誰でも同じ結果になり、UI の検証もテストもできます。金・土は埋まりやすく、2 名専用の MIST は最も埋まりやすい、といった実際の予約サイトに近い偏りを持たせました。満室の棟は選択できず、選択中の棟が満室になった場合は空いている棟へ自動で切り替わります。
- **料金ロジックの分離** — 価格・割引・税の定義を `src/data/pricing.ts`、計算を `src/lib/pricing.ts` に集約。UI には一切の金額をベタ書きせず、TOP のシミュレーターと予約ページが同じ関数を共有しています。Vitest で 16 件のテストを用意し、連泊割引・追加人数・オプションの単位（泊単位／滞在単位）・定員の丸め込みを検証しました。
- **状態の受け渡し** — 宿泊条件は URL クエリ（共有・戻る操作に強い）と localStorage（再訪時の復元）の両方へ書き出し。`try/catch` で保存できない環境でも機能を止めません。
- **JavaScript を最小に** — UI ライブラリもアニメーションライブラリも使わず、素の TypeScript で実装。ページあたりの JS は gzip 約 13〜16KB（うち約 5KB は Astro のページ遷移機能、残りが料金計算・予約 UI・ヘッダー・ギャラリー）です。
- **出現アニメーション** — `clip-path` でマスクされた要素は IntersectionObserver が「交差していない」と判定するため、`requestAnimationFrame` で間引いた位置判定に切り替えています。JS 無効時は初期状態を適用せず、すべての要素が最初から見える設計です。
- **画像** — `astro:assets` で AVIF / WebP と srcset を自動生成。LCP 候補の HERO のみ `eager` + `fetchpriority="high"`、それ以外は遅延読み込み。`<picture>` は `display: contents` にして、`object-fit` が意図通り効くようにしています。
- **フォント** — 日本語フォントはサイト内で実際に使う文字だけを抽出してサブセット化（`scripts/build-fonts.mjs`）。フルセット約 3.2MB を 3 ファイル計約 375KB（Latin の Jost 26KB を含めて約 400KB）へ圧縮し、本文用の 2 書体だけを preload しています。
- **アクセシビリティ** — セマンティック HTML、見出し階層、`focus-visible`、44px 以上のタップ領域、フルスクリーンメニューのフォーカストラップと Esc、`<dialog>` によるライトボックス、フォームのラベルとエラーの `role="alert"`、`prefers-reduced-motion` 対応。
- **架空案件としての誠実さ** — 実在施設と誤認されないよう、TOP・フッター・アクセス・予約完了画面にコンセプトプロジェクトである旨を明記。構造化データも `LodgingBusiness` ではなく `CreativeWork` として記述し、存在しない事業体を事実として登録していません。

## 7. レスポンシブ設計

375 / 390 / 430 / 768 / 1024 / 1440 / 1920px を対象に検証しています。「PC を縦に並べただけ」にしないため、スマホでは以下を作り分けました。

- ヘッダーはフルスクリーンメニューへ切り替え、画面下部に固定 CTA を追加
- 客室比較表は 1 列目を固定した横スクロールに変更
- 予約ステップは、上部のステップ一覧を進捗バー + 現在地表示に置き換え（一覧は読み上げ用に DOM へ残す）
- ギャラリーは高さを揃えた横スクロールのフィルムストリップ
- HERO は `object-position` を PC / スマホで変え、9:16 でも建物が切れないように

横スクロールの発生は Playwright で全ページ × 3 ビューポートを自動チェックしています（`npm run qa:screenshots`）。

## ポートフォリオ一覧用の紹介文（約 130 文字）

> 箱根の森に建つ架空のプライベートヴィラ「EMBER & MOSS」のコンセプトサイト。ブランド設計からコピー、UI 設計、実装までを一貫して制作しました。料金がその場で分かるシミュレーターと、スマホ最適化した 5 ステップの予約 UI が中心です。

## 営業時に説明する「見どころ」5 つ

1. **料金の不安をその場で消す設計** — TOP に置いた料金シミュレーターで人数・泊数・食事・オプションの総額が即座に出ます。入力した条件はそのまま予約ページへ引き継がれ、再入力が発生しません。
2. **本番同等の予約 UI** — 5 ステップ、ステップごとのバリデーション、日付に連動した空室表示、定員や満室で選べない棟の自動無効化、常時表示の料金サマリー。決済以外は実サービスと同じ体験を再現しています。
3. **スマホを主画面として作っている** — 画面下部の固定 CTA、横スクロールの比較表、進捗バー付きのステップ UI。PC のレイアウトを縮小しただけの画面が 1 つもありません。
4. **写真頼みにしない速度設計** — 日本語フォントを使用文字だけにサブセット化（約 1/8）、AVIF / WebP の自動生成、UI ライブラリ非使用で JS は gzip 約 15KB。LCP は約 0.3 秒、CLS は 0.003 です。
5. **架空案件であることを設計に織り込んでいる** — 実績や受賞歴を偽らず、コンセプトプロジェクトである旨をデザインを壊さない形で明示。誠実さも含めて納品物として提示できます。
